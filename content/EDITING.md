# 修改个人资料

`profile.json` 是主页个人资料的内容源。修改这里后，由网站读取并展示；无需把个人介绍写入页面布局代码。项目详情使用网站的项目内容文件维护，本文件不重复保存项目长文。

## 基本格式

用户可见的文字一般使用中英双语对象：

```json
{
  "zh": "机器人学习与 AI 系统",
  "en": "Robot Learning & AI Systems"
}
```

编辑时同时维护两种语言。保留 JSON 的英文双引号和逗号；最后一个字段后面不要添加逗号。`true`、`false` 和 `null` 不加引号。

## 字段说明

| 字段 | 用途 | 修改方法 |
| --- | --- | --- |
| `schema_version` | 数据结构版本 | 只改文字时保持 `1`。 |
| `updated` | 本次资料更新日期 | 使用 `YYYY-MM-DD`，只在内容实际更新后修改。 |
| `default_language` | 默认语言 | 使用 `zh` 或 `en`，并与页面语言逻辑保持一致。 |
| `name` | 中文名与英文名 | 分别修改 `zh`、`en`。 |
| `tagline` | 姓名下的一句话方向 | 保持简短，建议围绕两三个长期主题。 |
| `bio` | 个人介绍段落 | 每个对象是一段，按数组顺序展示。 |
| `contact.email` | 公开联系邮箱 | 填写愿意公开的邮箱。 |
| `contact.github` | GitHub 主页链接 | 使用完整的 `https://github.com/用户名`。 |
| `education` | 教育经历 | 按时间倒序维护学校、学位、起止日期和补充说明。 |
| `experience` | 实习经历 | 按时间倒序维护机构、角色、日期与简短职责。 |
| `skills` | 技术与实践方向 | 每项使用双语对象；用项目能支持的技术名称。 |
| `recognition` | 奖项、专利与软件著作权 | 按类型维护，区分申请、实审、授权与登记状态。 |

## 教育与实习

教育条目的 `start`、`end` 使用 `YYYY-MM`。尚未毕业时将 `expected` 设为 `true`；毕业后核对实际日期，再改成 `false`。

实习条目的 `end` 为 `present` 时表示当前仍在进行。结束后替换为实际月份。`description` 是双语段落数组，可增加或删减条目。

原力灵机经历依据当前项目背景补入，简历中的旧实习经历写至 2026 年 4 月。后续有新项目时，应优先更新项目详情，再把稳定、可核实的职责补到这里。实习描述使用“参与”“执行”“开展”等符合实际分工的措辞；明确独立负责的部分，可以在核对证据后具体说明。

## 奖项、专利与软件著作权

`recognition[].type` 目前使用三种值：

- `award`：竞赛、奖学金等荣誉。
- `patent`：专利申请或已授权专利。
- `software-copyright`：软件著作权登记。

`featured: true` 表示可供首页精选，`false` 表示适合完整列表或详情页。`date` 使用已确认的年份或时间段；未确认时保留 `null`。

涉及知识产权的条目还包含：

- `identifier`：申请号、专利号或登记号，作为字符串保存。
- `category`：具体成果类型。
- `status`：当前展示的状态，中英文应一致。
- `role`：本人在学生作者中的顺序，不应改成“所有作者第一作者”或“唯一作者”。

发明申请 `202411648348.1` 在简历中写为实审；外观设计专利 `202430738379.0` 写为已授权。两者当前按简历记载展示。后续若有新证书或公开状态记录，再更新 `status`。软件著作权属于登记成果，不计作论文。

中文成果名称依据简历整理；英文名称是便于阅读的译名，若已有证书、学校或机构的官方英文名称，应优先替换为官方写法。

## 公开内容边界

本文件不包含电话、年龄、政治面貌、住址、内部机器地址、访问凭据或私有数据路径。增加内容时也保持这一范围。模型结果、性能数值和具体技术贡献放在项目详情中，连同实验条件与本人分工一起维护。

## 修改后检查

在网站仓库根目录运行以下命令，确认 JSON 能解析：

```bash
python3 -m json.tool content/profile.json > /dev/null
```

然后查看中英文页面，检查段落长度、日期、联系方式与成果状态。保存并提交修改后，按仓库已有的 GitHub Pages 发布流程更新网页。
