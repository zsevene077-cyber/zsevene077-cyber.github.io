NexArm: capture, transcoding, and data integrity

I contribute to multi-camera capture and background transcoding for robot data, focusing on sustained writes, queue behavior, timestamps, and consistency of derived files.

Multi-camera · Video · Python · Windows

The question

How can post-capture processing be faster while preserving source data and consistent outputs?

My contribution

  • Work on multi-camera recording, robot-state reads, background queues, and transcoding development and diagnosis.
  • Compare transcoding concurrency on the same sealed recordings, checking MP4 hashes, timestamps, and source-data hashes.
  • Test real cameras alongside state reads from static arms, verify saved output and decoded frame counts, and distinguish this from motion-following acceptance.

Conditions and scope

A Windows background transcoding queue; 4 versus 8 parallel streams on the same two sealed recordings, totaling 3,090 frames. A separate real-device, static-arm read test produced 14 recordings over approximately 30 minutes.

How to interpret the result

The transcoding result is an offline comparison using two recordings. The static-arm read test produced 148 derived MP4s and validated capture and processing within that scope. It did not establish motion following, mechanical control performance, or training-grade video/state alignment.

What I learned

For data-system optimization, I want to answer both questions: is it faster, and can the resulting data still be trusted?
